# QMC6310 (magnetómetro 3 ejes)

## Rol en el proyecto
Magnetómetro de respaldo interno de la T-Beam Supreme, para comparar con el MMC5983MA externo. Sirve para orientación (rumbo) y como redundancia.

## Datos clave
| Parámetro | Valor | Fuente |
|---|---|---|
| Tipo | magnetómetro 3 ejes, salida digital 16 bit | driver SensorLib (`SensorQSTMagnetic`), resumen |
| Interfaz | **solo I2C** (el driver no tiene SPI) | driver SensorLib; `MagnetometerDrv` |
| Direcciones I2C | **0x1C** (variante QMC6310U) y **0x3C** (variante QMC6310N) | `SensorQSTMagnetic.hpp`: `QMC6310U_SLAVE_ADDRESS = 0x1C`, `QMC6310N_SLAVE_ADDRESS = 0x3C`; `LoRaBoards.cpp` escanea 0x1C y 0x3C |
| ID de chip | reg 0x00 (`REG_0x00_CHIP_ID`), valor esperado **0x80** para QMC6310U/N | driver: `QMC6310_CHIP_ID = 0x80` |
| Rangos (full scale) | ±2 G, ±8 G, ±12 G, ±30 G | driver `setFullScaleRange`; ejemplo LilyGO |
| Sensibilidad | 30 G → 1000 LSB/G · 12 G → 2500 LSB/G · 8 G → 3750 LSB/G · 2 G → 15000 LSB/G | driver (`setFullScaleRange`) |
| ODR | 10, 50, 100, 200 Hz | driver `setOutputDataRate` (acepta solo estos valores); comentario del ejemplo LilyGO |
| OSR (sobremuestreo) | 1, 2, 4, 8 | driver `setOversamplingRate`; ejemplo LilyGO |
| DSR (submuestreo) | 1, 2, 4, 8 | driver `setDownsamplingRate`; ejemplo LilyGO |
| Modos | SUSPEND, NORMAL, SINGLE_MEASUREMENT, CONTINUOUS_MEASUREMENT | driver `setOperationMode`; ejemplo LilyGO |
| Datos | 6 bytes (X, Y, Z; LSB primero) desde reg 0x01 | driver `readData` |
| Datasheet oficial | no localizado en qstcorp.com (la página de QST no lista el QMC6310) | ver Incertidumbres |

## Interfaz y pines
**I2C0 de la placa** (fuente: `utilities.h` del ejemplo LilyGO, bloque `T_BEAM_S3_SUPREME_SX1262`):
- `I2C_SDA` = GPIO **17**
- `I2C_SCL` = GPIO **18**
- Bus I2C0 = `Wire`. El bus `Wire1` (GPIO 42 SDA / 41 SCL) va al PMU, no a estos sensores.

**Dirección**: 0x1C (QMC6310U) o 0x3C (QMC6310N). El ejemplo LilyGO prueba primero 0x1C y luego 0x3C. Para saber cuál lleva la placa, escanear el bus (ver Trampas).

**Velocidad I2C**: no se confirmó en fuente oficial (ver Incertidumbres). El `I2CScanner` del repo LilyGO es útil para verificar la presencia.

## Registros clave
Del driver `SensorQSTMagnetic.hpp` (SensorLib). Estas direcciones no se verificaron contra un datasheet oficial.

| Reg | Nombre (driver) | Función |
|---|---|---|
| 0x00 | REG_0x00_CHIP_ID | ID de chip, esperado 0x80 |
| 0x01–0x06 | REG_0x01_LSB_DX … REG_0x06_MSB_DZ | datos X, Y, Z: LSB/MSB por eje (6 bytes, little-endian) |
| 0x09 | REG_0x09_STAT | bit 0 = DRDY (dato listo), bit 1 = overflow |
| 0x0A | REG_0x0A_CMD1 | bits 1:0 modo (`MODE`), bits 3:2 ODR, bits 5:4 OSR, bits 7:6 DSR |
| 0x0B | REG_0x0B_CMD2 | bit 7 = reset (escribir 0x80, luego 0x00); bit 6 = SET/RESET (`setRegBit`/`clrRegBit`); bits 3:2 = rango |
| 0x29 | REG_0x29_SIGN | registro de signo (definido en el driver, uso no documentado) |

Valores de ODR en el registro 0x0A bits 3:2: 00 → 10 Hz, 01 → 50 Hz, 10 → 100 Hz, 11 → 200 Hz (driver `setOutputDataRate`).

Valores de rango en el registro 0x0B bits 3:2: 00 → 30 G, 01 → 12 G, 10 → 8 G, 11 → 2 G (driver `setFullScaleRange`).

## Configuración relevante para nuestro uso
- **ODR**: 200 Hz es el máximo que acepta el driver. Usar 100 o 200 Hz para ver datos de vuelo sin pérdida.
- **Rango**: ±8 G (3750 LSB/G) da mejor resolución; ±30 G (1000 LSB/G) da más margen antes de saturar. La elección depende del campo que se espere medir (no verificado para el entorno del cohete).
- **OSR y DSR**: 1 para la mayor tasa.
- **Modo**: CONTINUOUS_MEASUREMENT para telemetría.
- **Calibración**: el ejemplo LilyGO recalibra en "figura de ocho" antes de usar la brújula. El ejemplo `qmc6310_calibrate` de SensorLib hace lo mismo.
- **Declinación magnética**: el ejemplo usa `setDeclination` con −3°20′ (valor de ejemplo del código; no verificado para Santa Fe de Antioquia).

## Alimentación y tiempos
| Evento | Tiempo | Fuente |
|---|---|---|
| Reset (cmd 0x80 → 0x00) | 10 ms de espera | driver `reset()` |
| Espera tras reset en init | 20 ms | driver `initImpl` (`hal->delay(20)`) |
| Tensión de alimentación | 2.5–3.6 V (LCSC, no oficial) | ver Incertidumbres |
| Rail en la placa | ALDO1 y ALDO2 a 3.3 V (`LoRaBoards.cpp`) | `LoRaBoards.cpp`, bloque "Sensor" |

El `LoRaBoards.cpp` apaga y vuelve a encender ALDO1, ALDO2 y BLDO1 en arranque en frío (250 ms de espera), para no dejar el bus ocupado. Este comportamiento no ocurre en un despertar por sueño.

## Trampas y notas
1. **1500 Hz en la tabla del equipo no es válido en el driver.** El driver acepta solo 10, 50, 100 y 200 Hz. Un valor de 1500 Hz daría error "Invalid output data rate".
2. **U o N**: la dirección cambia entre 0x1C (U) y 0x3C (N). El driver identifica el modelo por la dirección, y el ID de chip es 0x80 en ambos.
3. **Escáner LilyGO**: el `switch` de `LoRaBoards.cpp` tiene `case 0x51:` que cae en `case 0x1C:`. La dirección 0x51 es la del RTC PCF8563, así que el escáner podría etiquetar mal un dispositivo como QMC6310U.
4. **Corte de alimentación en arranque**: el ALDO del sensor se apaga y enciende en el arranque en frío. Si se mide justo después, esperar al menos 20 ms tras encender.
5. **Sensor no es el MMC5983MA**: no es el mismo chip. Las unidades (LSB/G) y la sensibilidad son distintas. No mezclar código de drivers del MMC5983MA.
6. **Core Electronics retiró el breakout**: el breakout PiicoDev QMC6310 se marca como retirado en su sitio. No depender de esa placa para pruebas.

## Incertidumbres
- **Datasheet oficial no localizado**: qstcorp.com no lista el QMC6310 (sí QMC6308/6309). Una copia del datasheet aparece en LCSC (dominio no oficial, no descargada); al intentar leerla no devolvió contenido, así que no se usó para registros ni tensiones. Pedir a QST el datasheet (business@qstcorp.com, según su web).
- **Tensión de alimentación y consumo**: solo de LCSC (2.5–3.6 V; sin verificar).
- **Velocidad I2C máxima**: no confirmada.
- **Modo single y power-down**: el driver tiene `SINGLE_MEASUREMENT`, pero no se confirmó el tiempo de conversión.
- **Orden de bits del modo** (SUSPEND/NORMAL/SINGLE/CONTINUOUS en 0x0A bits 1:0): el código los asigna 0x00 a SUSPEND, pero los valores de 0x01–0x03 para los demás modos se leyeron por orden del `switch`, sin verificar en el datasheet.
- **Mapeo OSR/DSR a bits**: el driver define los valores por código, pero no se verificó el orden de los bits 5:4 y 7:6 en la hoja de registros oficial.
- **Desviación de cero y sensibilidad real**: no documentadas en fuente oficial.
- **Diferencia QMC6309 vs QMC6310**: el ejemplo LilyGO soporta ambos con una dirección distinta (0x7C para QMC6309), pero no se confirmó en el datasheet de QST cuál modelo lleva la placa.
